# 14B trusted browser transport boundary

Date: 2026-11-01. Owner: Codex. Scope: disconnected browser adapter with synthetic API tests and a repository integration test.

- Added `src/background/enrollment-transport.ts`: browser-derived target observation and MessageSender projection, exact-document sends, time checks around lookup, bounded waits and generic no-retry failures. No global chrome access at module initialization, production import, listener, permission change or content injection.
- Added strict detached dispatch parsing in `src/shared/enrollment-dispatch.ts`. Commands, selection arrays and matching deadlines are validated before browser access.
- Added 55 cases in `tests/unit/enrollment-transport.test.ts`, including Chrome type compatibility, document replacement/cache/prerender/error states, origin/extension mismatch, missing metadata, private tab-field omission, command validation, clock changes, delayed lookup, stalled send, cancellation, detached inputs and durable repository integration.
- Targeted transport/dispatch checks: 91 tests passed. Final integration: lint, 936 tests across 27 files, TypeScript and production/MV3 build passed. Isolated Chromium 156.0.8078.4 extension E2E passed. Hosted CI pending publication.
- Initial typecheck exposed null-narrowing and intentionally malformed MessageSender fixture typing; both were corrected before the final successful full check/build.
- Browser API evidence: [getFrame](https://developer.chrome.com/docs/extensions/reference/api/webNavigation#method-getFrame) supports document ID plus matching tab/frame identifiers; [sendMessage](https://developer.chrome.com/docs/extensions/reference/api/tabs#method-sendMessage) supports a specific document and rejects connection errors; [MessageSender](https://developer.chrome.com/docs/extensions/reference/api/runtime#type-MessageSender) supplies extension/tab/frame/document/lifecycle/origin metadata. The required webNavigation permission remains absent.
- The injected APIs were synthetic. Isolated timetable E2E does not exercise this disconnected transport or establish signed-in portal behavior. No live host, selectors, real submission/result extraction, precision timing or human acceptance was verified.
- Limits: one-use sending still requires the repository owner; exact document targeting does not establish current DOM/selection validity. Incoming replies must use actual runtime sender metadata and existing reply validation. No runtime enrollment RPC is enabled.
- Next bounded candidate: 14B authenticated executor reply bridge, projecting the actual browser sender separately from untrusted payloads and feeding the repository through a disconnected, synthetic-tested handler.
